# PRD 质量评审 Checklist

这份文档是主 SKILL.md 阶段 A0 的深入补充。读 PRD 时按六个维度逐项扫描，找出需求的坑。

## 评审视角

你的角色是一位经验丰富的 QA 工程师。不是来挑字眼的，而是在问自己三个问题：
1. **这条需求我能落成具体的测试用例吗？** 能则通过，不能则 → 模糊或不可测
2. **这条需求的边缘/异常场景被覆盖了吗？** 没覆盖 → 奇脉
3. **这条需求和其他需求有没有打架？** 有则矛盾

不要无端扩展——PRD 不可能穷举所有场景。你的任务是找出**会显著影响实现质量**的缺口。

---

## 维度 1：缺失（Missing）

PRD 完全没提、但开发时一定会遇到的场景。

### 常见缺失点（按场景）

**认证/授权类需求**
- 未登录时的行为（拦截？跳转？）
- Token 过期如何处理
- 权限不足的提示和响应
- 多端登录策略（互踢 / 共存）

**数据提交类需求**
- 字段长度上限/下限
- 必填 vs 选填
- 特殊字符处理（Emoji、HTML、SQL）
- 国际化输入（中文、全角、阿拉伯文 RTL）

**业务操作类需求**
- 操作成功后的页面/状态
- 操作失败后的处理
- 操作进行中的 loading 态
- 操作的撤销/重做

**并发类需求**
- 重复提交怎么处理（幂等）
- 多人操作同一资源（乐观锁/悲观锁）

**网络类需求**
- 弱网/断网的降级行为
- 超时时长及超时后的提示
- 重试策略

**数据生命周期**
- 数据何时过期/归档/删除
- 删除是物理还是软删除
- 批量操作的上限

**监控与可观测性**
- 关键操作是否埋点
- 审计日志记录哪些字段
- 异常报警的触发条件

### 如何表达
**不要说**："PRD 漏了超时处理"
**要说**："PRD 未明确接口超时时长及超时后的用户提示，建议补充（建议默认 15s 超时，提示'请求超时，请重试'）"

## 维度 2：矛盾（Contradiction）

前后不一致、互相打架。

### 常见模式

**文档内部矛盾**
- 前文说"最多 10 个"，后文示例用了 12 个
- 一处说"仅管理员可见"，另一处描述普通用户也能看到

**与常识矛盾**
- "支持 1 亿并发 + 2C2G 服务器部署"（硬件与性能不匹配）
- "密码错 3 次锁定 24 小时，但用户仍可登录"（矛盾性描述）

**与行业惯例矛盾**
- "密码明文存储以便找回"（安全红线）
- "不需要 HTTPS"（行业基本要求）

**隐式矛盾**
- 业务规则 A 与业务规则 B 在某个边缘输入上冲突（如"免费用户每月 10 次" + "新用户注册送 20 次"，累加后超过免费额度）

### 如何表达
**不要说**："有冲突"
**要说**："AC-3.1 要求支持 10 万 QPS，但 AC-3.5 要求每次写入都强同步刷盘，两者矛盾。需要确认：是放宽性能目标、还是改用异步刷盘？"

---

## 维度 3：模糊（Ambiguous）

用词含糊、缺具体指标。测试时不知道什么算"通过"。

### 模糊词红黑榜

| 模糊词 | 需追问 |
|--------|--------|
| 快速响应 | 多少毫秒？P50/P99？ |
| 大量数据 | 多少条？MB 级还是 GB 级？ |
| 友好提示 | 具体文案？弹窗还是 toast？ |
| 支持主流浏览器 | 具体哪几款？哪个版本起？ |
| 高可用 | SLA 几个 9？RTO/RPO？ |
| 必要时 | 触发条件是什么？ |
| 适当 | 依据什么判断？ |
| 合理 | 边界在哪？ |
| 尽量 | 硬性约束还是 best effort？ |
| 等等 | 完整列表是什么？ |

### 如何表达
**不要说**："'快速响应'不清楚"
**要说**："AC-2.3 中'快速响应'未量化。建议明确：P95 响应时间 < 500ms（业务常见阈值）"

---

## 维度 4：不可测（Untestable）

无法用黑盒手段验证。

### 常见反例

**纯主观描述**
- "界面美观大方" → 美观的标准是什么？
- "交互流畅自然" → 怎么量化流畅？

**实现依赖**
- "使用 Redis 缓存" → 缓存的可观察副作用是什么？测试时看什么？
- "重构代码以提升性能" → 怎么证明重构成功了？

**黑盒不可见**
- "内存占用降低 30%" → 需要性能剖析工具，不是常规 QA 手段
- "代码行数减少" → 这是代码审查的事，不是测试

### 转化思路
不可测的需求，要么：
1. **改写为可测的代理指标**（如"美观"→"符合 xx 设计规范"+截图对比）
2. **标注为非 QA 范围**（如代码质量→走代码审查）
3. **补充可观察的业务指标**（如"用户满意度"→"问卷评分 ≥ 4.0"）

### 如何表达
"AC-1.5 '界面美观'无法用黑盒手段验证。建议要么删除，要么改为可测指标：'视觉对比与设计稿一致度 ≥95%（通过截图对比工具）'"

---

## 维度 5：奇脉（Edge Cases）

边界值、异常场景缺失。这是 QA 最擅长的维度。

### 按类型过一遍

**数值边界**
- 0、负数、极大值
- 边界的"恰好等于"和"超出 1"
- 浮点精度（0.1+0.2）
- 货币的最小单位（分）

**字符串边界**
- 空串、纯空白
- 最大长度、最大长度+1
- 特殊字符（SQL/HTML/emoji/零宽）
- 多字节字符（中文、阿拉伯文）

**集合边界**
- 空集合
- 单元素集合
- 超大集合（性能）

**时间边界**
- 当前时刻、未来、过去
- 跨日、跨月、跨年
- 闰年 2 月 29 日
- 夏令时切换
- 时区差异

**状态边界**
- 初始状态、终态、异常态
- 状态迁移的非法路径
- 并发修改同一状态

**资源边界**
- 配额刚好用完
- 文件刚好到达上限
- 磁盘/内存满的情况

### 如何表达
"AC-2.1.2 文件大小 50MB 限制未说明：(1) 刚好 50MB（边界值）是否通过；(2) 前端还是后端校验；(3) 分片上传是否按总大小算。建议补充"

---

## 维度 6：依赖（Dependencies）

与其他模块/系统耦合未说清。

### 常见盲点

**外部服务依赖**
- 第三方 API（支付、短信、地图）挂了怎么办？
- 依赖服务的 SLA 是多少？降级策略？
- 幂等保证（支付回调重复收到怎么办？）

**内部系统依赖**
- 依赖的中台接口协议稳定吗？
- 异步消息丢失如何处理？
- 依赖的数据是否一致？

**前后端契约**
- 字段类型（前后端类型是否对齐）
- 时间格式（前端发 ISO，后端要时间戳？）
- 错误码规范

**环境依赖**
- 需要特定域名/IP 白名单？
- 需要特定浏览器扩展/权限？
- 需要用户授权摄像头/位置？

### 如何表达
"AC-2.3 '[某外部服务调用]'依赖第三方[服务名称]。建议补充：(1) [服务]超时阈值；(2) 发送失败时的降级（重试？换通道？）；(3) 网关限流下的用户体验。"

## 默认处理建议的选择

评审出的每个问题，给一个**具体可选的处理建议**，让用户只需确认"√"或稍作调整，不用每条都自己输入。

建议格式：
- **假定（Assumption）**：如果 PRD 没说但行业通常这么做，给一个默认值
- **补全（Fill-in）**：用例中按某个合理默认生成
- **搁置（Skip）**：该场景先不测，等 PRD 更新
- **追问（Ask PM）**：太关键的矛盾必须等产品明确

### 例子

```
问题：AC-2.1.2 未明确大小校验时机（前端/后端）
默认建议：【补全】同时测前端（JS 拦截）和后端（413 响应）两个用例
备选方案：【搁置】不测，等 PRD 明确后补
```

```
问题：AC-3.1 性能目标与 AC-3.5 同步刷盘要求矛盾
默认建议：【追问 PM】这是关键矛盾，必须先明确放宽哪个约束
```

## 严重等级

给每条问题标等级，帮用户快速判断关注优先级：

- 🔴 **阻塞（Blocker）**：不解决就无法设计有效用例，或会导致用例方向错误
- 🟡 **重要（Major）**：会导致用例缺漏或覆盖不准
- 🟢 **建议（Minor）**：改进 PRD 质量，但不阻塞当前工作

---

## 避免的反面

- ❌ 吹毛求疵：每个词都挑刺（"可以"改成"能够"更好）
- ❌ 超出 QA 职责：质疑业务必要性（"这功能有人用吗？"）
- ❌ 假设全部错：PRD 没写的不等于没想过，有可能是其他文档已经说了
- ❌ 一次性太多：同类问题合并成一条，避免刷屏
