# 测试设计方法详解

这份文档是主 SKILL.md 的深入补充。需要为某个功能设计用例时，找对应的方法按例子操作。

## 1. 等价类划分（Equivalence Partitioning）

### 核心思想
把无限的输入域划分成有限的"等价类"，每个等价类选一个代表即可。

### 划分步骤
1. 找出所有输入条件
2. 对每个输入条件，确定有效等价类（valid）和无效等价类（invalid）
3. 为每个等价类设计至少一条用例

### 例子：用户名字段（要求 3-20 位，字母数字下划线）

| 等价类 | 类型 | 代表值 |
|-------|------|-------|
| 3-20 位字母数字下划线组合 | 有效 | `user_01` |
| 长度 < 3 | 无效 | `ab` |
| 长度 > 20 | 无效 | 21个字符 |
| 包含特殊字符 | 无效 | `user@01` |
| 包含中文 | 无效 | `用户01` |
| 仅数字 | 有效（若规则允许）或无效 | `123` |
| 空字符串 | 无效 | `` |

### 何时用
几乎每个有输入的功能都要用。它是负向用例的主要来源。

## 2. 边界值分析（Boundary Value Analysis）

### 核心思想
bug 高发在边界上。对每个数值/长度边界，测试恰好在边界和刚好超出边界的值。

### 边界三件套
对"值在 [min, max] 范围内"的约束：
- `min - 1`（越下界，应拒绝）
- `min`（等于下界，应接受）
- `min + 1`（刚进入范围，应接受）
- `max - 1`（接近上界，应接受）
- `max`（等于上界，应接受）
- `max + 1`（越上界，应拒绝）

### 例子：年龄字段 [18, 120]
测值：17, 18, 19, 119, 120, 121

### 特殊边界（容易漏）
- **空**：空字符串、null、undefined、空数组
- **单元素**：单字符、单个元素的数组
- **0**：数值的 0
- **负数**：即使业务上应该是正数，也要测负数传入时的行为
- **极大值**：INT_MAX、字符串 1MB、列表 10 万项
- **特殊字符**：空格、Tab、换行、emoji、SQL 特殊字符、HTML 标签、零宽字符

### 日期/时间边界
- 闰年 2 月 29 日
- 月份最后一天、第一天
- 跨年（12 月 31 日 → 1 月 1 日）
- 时区切换、夏令时
- 1970-01-01（unix 时间戳起点）、2038-01-19（32 位 overflow）

## 3. 因果图 / 判定表（Cause-Effect Graph / Decision Table）

### 核心思想
多个条件组合决定不同结果时，穷举组合容易爆炸（n 个条件有 2^n 种组合）。判定表帮你挑出有意义的组合。

### 例子：订单折扣规则
- 条件 A：是会员
- 条件 B：订单金额 > 500
- 条件 C：使用了优惠券

完整组合 2³ = 8 种：

| 用例 | A会员 | B>500 | C优惠券 | 折扣策略 |
|-----|------|------|--------|---------|
| 1 | ✓ | ✓ | ✓ | 会员折 + 满减 + 券（最优组合） |
| 2 | ✓ | ✓ | ✗ | 会员折 + 满减 |
| 3 | ✓ | ✗ | ✓ | 会员折 + 券 |
| 4 | ✓ | ✗ | ✗ | 仅会员折 |
| 5 | ✗ | ✓ | ✓ | 满减 + 券 |
| 6 | ✗ | ✓ | ✗ | 仅满减 |
| 7 | ✗ | ✗ | ✓ | 仅券 |
| 8 | ✗ | ✗ | ✗ | 原价 |

### 什么时候用
- 业务规则里有 if-and-or-then 这类组合
- PRD 中出现"根据 X 和 Y 判断 Z"
- 功能文档里有表格描述规则

### 什么时候别用
- 条件超过 5 个时完整判定表会爆炸，需要结合等价类合并同类项
- 只有 1-2 个条件时直接写场景用例更清楚

## 4. 场景法（Scenario Testing）

### 核心思想
用户不是输入单个字段，而是走一条业务流程。按"主流程—备选流程—异常流程"组织用例。

### 结构模板
每个功能至少设计三类场景：

**主流程（Happy Path）**：最常见的正确使用路径。比如下单：浏览 → 加购 → 结算 → 支付 → 收货。

**备选流程（Alternative Path）**：中途做了合法但不同的选择。比如：浏览 → 加购 → 结算 → **修改地址** → 支付 → 收货。

**异常流程（Exception Path）**：过程中遇到错误或异常。比如：浏览 → 加购 → 结算 → 支付 **→ 支付失败** → 重试 / 取消。

### 例子：[某业务流程]
- **主流程**：[步骤A] → [步骤B] → [步骤C] → [步骤D] → [成功结果]
- **备选流程 1**：[步骤A] → [步骤B] → [条件变化] → [替代步骤] → [成功结果]
- **备选流程 2**：[步骤A] → [发现更优路径] → [切换方式]
- **异常流程 1**：[步骤A] → [前置条件不满足] → 提示
- **异常流程 2**：[步骤A] → [步骤B] 时 [异常发生] → 提示 → 重试
- **异常流程 3**：[成功结果] 但 [后续步骤] 超时 → 回退到 [兜底方案]

## 5. 错误推测（Error Guessing）

### 核心思想
基于经验猜"哪里容易出 bug"，针对性设计用例。这是经验驱动的方法，没有机械步骤。

### 通用坑点清单（按场景）

**输入相关**：
- 前后有空格的输入
- 全角字符（如全角数字 `１２３`）
- 多字节字符/emoji/零宽字符
- 粘贴进来的带格式富文本
- 浏览器自动填充带来的意外值
- 中英文标点混用

**时间相关**：
- 服务器时间 vs 客户端时间不一致
- 跨时区用户
- 夏令时切换当天
- 闰秒、闰年
- 时间戳精度：秒 vs 毫秒
- 时间倒流（用户改本地时间）

**数字相关**：
- 浮点精度（0.1 + 0.2 !== 0.3）
- 科学计数法输入（1e10）
- 整数溢出
- 负数和零
- 货币小数位处理

**文件上传**：
- 超大文件
- 0 字节文件
- 文件名带特殊字符、空格、中文
- 双后缀（shell.jpg.exe）
- 文件头与后缀不符（jpg 内容实际是 exe）
- 上传中断、重复上传同一文件

**并发/幂等**：
- 连续点击提交按钮
- 双端同时操作同一资源
- 订单号重复
- 幂等 key 失效

**权限**：
- 未登录访问受保护接口
- 登录但未授权访问他人资源（水平越权）
- 低权限访问高权限功能（垂直越权）
- token 过期
- token 被篡改

**状态**：
- 数据被他人删除后，当前页面刷新
- 流程到一半，前置状态变了
- 浏览器后退 / 前进
- 多标签页操作同一数据

**前端渲染**：
- 数据字段缺失时的 null/undefined 渲染
- 极长文本的布局破坏
- 极多数据项的性能卡顿
- 图片加载失败的占位

### 何时用
**总是用**。错误推测是对其他方法的补充。写完其他用例后，过一遍这个清单，补上遗漏的用例。

## 组合使用示例

对"[某个功能操作]"这个功能：

1. **等价类**：[输入A]格式（有效/无效）、[输入B]（有效/无效/过期/错误）
2. **边界值**：[输入A]长度、[输入B]长度
3. **因果图**：[条件A] × [条件B] × [条件C] 的组合
4. **场景法**：主流程（操作成功）、备选（中途取消）、异常（[异常场景1]、[异常场景2]）
5. **错误推测**：[错误推测点1]、[错误推测点2]、[错误推测点3]

最终 20+ 条用例来自这 5 个角度的组合，覆盖会比单用一种方法充分得多。
